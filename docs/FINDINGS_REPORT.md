# Findings Report — PIDE Macroeconomic Indicator Dashboard

## Executive summary

This project is a production-oriented macro-data pipeline and Streamlit dashboard for Pakistan, prepared for PIDE research economists. The current validated build contains **144,647 observations**, **1,209 unique literal series**, **23 datasets**, **0 validation errors**, and **3 warnings**. The 1,212-row series index intentionally retains three source-qualified duplicate literal labels; it is therefore not an error that the index-row count exceeds the unique-name count. The dashboard is a provenance-first analytical interface, not an alternative statistical publication: every chart should be read with its publisher, unit, frequency, coverage, and accounting basis in view.

The strongest engineering result is a reliable official-data spine. The State Bank of Pakistan (SBP) publishes three static JSON files that index its Economic Data library without a key, session, or HTML parsing requirement: the [750-entry main catalogue](https://www.sbp.org.pk/assets/dt_collection_75160/econmicMainDataNew.json), [9-entry real-sector catalogue](https://www.sbp.org.pk/assets/dt_collection_75160/econmicRealSectorData.json), and [153-entry external-sector catalogue](https://www.sbp.org.pk/assets/dt_collection_75160/econmicExternoaSectorData.json). Their nested structure is `{parent:{child:{frequency:{year:[entries]}}}}`; each entry exposes a dated `attachment` and often a `commulative_archive` containing the useful full-history workbook. The pipeline flattens 909 indexed file records into `sbp_file_catalog.csv`; this is the best available automation hook for SBP data and removes the need to parse the SBP website’s HTML.

A second durable result is the use of open Government of Pakistan SDMX 2.1 feeds. The two Ministry of Finance (MoF) feeds—[general government operations](http://sdmx.finance.gov.pk/GGO_Pakistan.xml) and [central government operations](http://sdmx.finance.gov.pk/CGO_Pakistan.xml)—and five Pakistan Bureau of Statistics (PBS) feeds—[CPI](https://www.pbs.gov.pk/wp-content/uploads/2020/07/CPI-1.xml), [merchandise trade](https://www.pbs.gov.pk/wp-content/uploads/2020/07/MET.xml), [quarterly national accounts](https://www.pbs.gov.pk/wp-content/uploads/2020/07/QNAG.xml), [producer prices](https://www.pbs.gov.pk/wp-content/uploads/2020/07/PPI.xml), [energy](https://www.pbs.gov.pk/wp-content/uploads/2020/07/ORSI.xml), and [labour](https://www.pbs.gov.pk/wp-content/uploads/2020/07/LMI.xml)—are static XML feeds with no key. They are the only wired machine-readable sources for fiscal operations, producer prices, labour, and energy.

The design deliberately does **not** make SBP EasyData a production dependency. Its [Developer Guide](https://easydata.sbp.org.pk/apex/f?p=10:22) documents a genuine per-series REST API, but access requires a user-generated key that expires after 90 days and is quota-limited to 2,000 requests per day and 250 per hour. EasyData is valuable as an opt-in enhancement for series without a satisfactory public archive (notably core inflation, numeric KIBOR, and a clean policy-rate series), not as the unattended pipeline’s single point of failure.

Three warnings remain after validation and are legitimate publication/data characteristics rather than software defects: both MoF SDMX operation feeds genuinely end at 2025-03-31 (approximately a 16-month publication lag), and one SBP credit borrower category is correctly zero in all reported periods. A warning is visible rather than suppressed so users can distinguish a stale official release from a pipeline failure.

## Scope and method

The source universe is restricted to official Government of Pakistan, SBP, and statutory-regulator material. The registry contains 75 catalogued sources: 32 Tier 1, 26 Tier 2, and 17 Tier 3. Of these, 24 sources have parsers wired into the current transformation registry; 23 contribute data to the current master. The index records 1,212 source-series rows and observed start/end dates, while the master retains the full observation history.

The pipeline is designed around reproducibility rather than a one-off download. It (1) refreshes the SBP catalogue, (2) resolves and downloads sources with content hashing and dated raw snapshots, (3) backfills PBS sources released one file per period, (4) converts registered files to a common long form, and (5) validates output. The canonical contract is:

```text
date | series | value | unit | source_id | frequency
```

The master is written to `data/processed/macro_master.parquet`, with source-level Parquet/CSV outputs and metadata alongside it. Every displayed item remains traceable to its source identifier and official page. This approach avoids a common dashboard failure mode: a polished chart that silently hides a changed source, an incompatible unit, or a discontinued series.

### Access behaviour and operational implications

PBS, MoF SDMX, FBR, NEPRA, and the main MoF site are usable by ordinary scripted retrieval from their official pages. SBP and EasyData need careful pacing: a burst can trigger a Cloudflare 403 that lasts beyond the running process. The fetcher enforces a four-second minimum interval per host and applies a sixfold backoff penalty after a 403. SBP’s NSDP SDMX endpoints, the MoF public-economy API host, and all directly tested OGRA paths are not viable unattended inputs; the official SBP catalogue and the open PBS/MoF XML feeds are intentionally used instead.

### SDMX interpretation note

The GoP feeds encode observations using opaque IMF ECOFIN-style indicator codes and do not provide `<Name>` elements. The pipeline keeps the original code in every displayed series name and uses a cached 303-label extract from the **IMF ECOFIN codelist solely for presentation labels**—the one permitted non-GoP reference. All observations remain from the GoP feeds. Four labels that could only be resolved ambiguously by code truncation were dropped rather than guessed.

Most importantly, SDMX `Q1`/`Q2`/`Q3`/`Q4` periods are **fiscal**, not calendar periods. FY2026 Q1 is July–September 2025. Cross-checking the QNAG feed with the independently parsed SBP quarterly workbook gives an exact correspondence under fiscal dating and a two-quarter error under calendar dating. The parser assigns period-end dates accordingly; interpreting these tokens as calendar quarters would misdate every turning point by six months.

## Recommended dashboard datasets and rationale

1. **SBP JSON catalogue:** use it first for new SBP work because it carries publisher-provided current and cumulative-archive URLs, not reverse-engineered links. The three official catalogue URLs are the project’s highest-value discovery input.
2. **PBS CPI SDMX plus the historical CPI workbook:** use [CPI-1 XML](https://www.pbs.gov.pk/wp-content/uploads/2020/07/CPI-1.xml) for current COICOP indices and weights, and the [historical workbook](https://www.pbs.gov.pk/wp-content/uploads/2020/07/indices_and_growth_rates_historical.xlsx) for published long-run CPI/RPI/WPI inflation measures. This supports an explicit price-basket story without inventing a core/non-food aggregate.
3. **Weekly SPI:** keep it for near-term food-price monitoring, but label it as a different basket from CPI and use the PBS release date rather than interpolating it into monthly CPI.
4. **SBP reserves, BOP trade and remittances:** [Forex reserves](https://www.sbp.org.pk/assets/document/Forex_Arch.xlsx), [BOP trade](https://www.sbp.org.pk/assets/document/exp_import_BOP_Arch.xls), and [country remittances](https://www.sbp.org.pk/assets/document/Homeremit_Arch.xlsx) combine long history, policy salience, and maintainable archive URLs.
5. **PBS MET SDMX:** use [MET XML](https://www.pbs.gov.pk/wp-content/uploads/2020/07/MET.xml) for long customs trade history and commodity detail, preserving its million-PKR customs basis.
6. **MoF general-government SDMX:** use [GGO XML](http://sdmx.finance.gov.pk/GGO_Pakistan.xml) as the best fully automated fiscal-operation source, but make its publication lag visible rather than implying a current fiscal position.
7. **PBS QNAG and SBP GDP workbooks:** use both only when price basis is explicit. The [QNAG feed](https://www.pbs.gov.pk/wp-content/uploads/2020/07/QNAG.xml) supports timely nominal/sectoral work; [SBP QGDP](https://www.sbp.org.pk/assets/document/QGDP.xlsx) supports the existing constant-price series.
8. **PBS ORSI and LMI:** retain the [energy feed](https://www.pbs.gov.pk/wp-content/uploads/2020/07/ORSI.xml) because it is the only located machine-readable monthly energy source; retain [LMI](https://www.pbs.gov.pk/wp-content/uploads/2020/07/LMI.xml) for historical labour context but not as a current labour-market signal.

## Automation architecture and tiering rationale

**Tier 1 — dashboard core.** Fully automated, stable, source-specific parsers or SDMX parsers produce validated long-form output. This includes the selected PBS/SBP archives and the seven GoP SDMX feeds. Tier 1 is the default `python -m etl.run_etl --tier 1` set.

**Tier 2 — automated acquisition, semi-structured interpretation.** The pipeline can obtain the file reliably enough, but parsing needs source-specific work, semantic review, or a decision about definition/continuity. Examples include additional SBP archive workbooks, PBS national accounts files, FBR collection PDFs, and survey microdata. A Tier 2 source must not silently become a dashboard headline merely because it was downloaded.

**Tier 3 — PDF/manual reference.** The file may be downloadable, but its content is PDF-first, very large, blocked, irregular, or not robustly parseable without human checking. MoF budget/fiscal PDFs, NEPRA reports and tariff determinations, and OGRA material belong here. Tiering is a reliability statement, not a judgement on the source’s analytical value.

The scheduled command performs catalogue → extract → backfill → transform → validate. Exit code 0 means success or warnings only; exit code 1 means a failed stage or at least one validation error. Raw inputs are hash-versioned, so a rerun records unchanged content instead of overwriting evidence. PBS backfill prevents a fresh clone from treating a single newest SPI/trade release as a complete history.

## Data quality, pitfalls, and non-negotiable basis warnings

> **Do not mix these series.** SBP trade is BOP basis in million USD; PBS summary trade is customs basis in million USD; PBS SDMX trade is customs basis in **million PKR**. They answer different statistical questions and must not be summed, substituted, or plotted as a single seamless line. Likewise, general government already consolidates federal and provincial activity—never add central-government operations to it. PBS SDMX quarterly GDP is nominal (about Rs 31.8 trillion for Jan–Mar 2026), while the SBP quarterly workbook is constant 2015-16 basic prices (about Rs 11.5 trillion for the same quarter); both can be correct and neither is comparable on an unqualified shared axis.

Additional limits are explicit in the dashboard: REER/NEER ends at December 2023; the PBS labour SDMX feed ends in 2021. The following lessons are codified in the parsers and validation logic:

- The old `sbp.org.pk/ecodata/` location returns a convincing HTTP 200 HTML page of roughly 204 KB even though the data file is absent. File acceptance must check magic bytes (`PK` for XLSX, `\xd0\xcf\x11\xe0` for XLS, `%PDF-` for PDF), not only HTTP status.
- SBP headers can change mid-sheet from datetime values to strings such as `Jul-18` or `Jun-26P`. Plain `pd.to_datetime` can silently discard the string half and truncate history while leaving a plausible-looking chart; parser-specific period coercion is required.
- The [SBP BOP trade archive](https://www.sbp.org.pk/assets/document/exp_import_BOP_Arch.xls) stacks annual fiscal-year and monthly blocks under one merged header. A loose fiscal-year regex previously matched datetimes and collapsed 2,106 monthly rows onto June year-ends; fiscal labels must be full-string matches.
- [IR-Corridor-Hist](https://www.sbp.org.pk/assets/document/IR-Corridor-Hist.xls) is standing-facility **usage**—amounts drawn and institution counts—not a policy-rate history. The policy rate comes from [Structure of Interest Rates](https://www.sbp.org.pk/assets/document/sir.pdf). Relabelling the former would fabricate a policy-rate line.
- In the [REER/NEER workbook](https://www.sbp.org.pk/assets/document/neer-reer.xls), the `Monthly Position` divider appears in the NEER column rather than the period column; parser control flow therefore detects it across the row.
- SBP reclassified private-sector credit to ISIC Rev. 4 in 2019. Same-named borrower categories before and after the change are not the same aggregate, so reclassified categories are stored as separately suffixed series rather than stitched together.
- SBP indents component rows one column further right than the aggregate rows that total them, and the indentation level changes between sheet vintages. A parser that reads a fixed label column therefore drops the aggregates while keeping their components: in [BroadMoney_M2_Arch](https://www.sbp.org.pk/assets/document/BroadMoney_M2_Arch.xls) the headline `Broad Money (M2) (A+B+C)` row moved one column left from the FY13 sheet onward, so the M2 total appeared to stop in 2012 while every component stayed current to 2026. The same defect hid SBP's published remittances `Total`. Row labels must be resolved by scanning all columns to the left of the first data column, not by reading one.
- Where a publisher states an aggregate, read the aggregate rather than reconstructing it from components. SBP's remittance corridors nest — Abu Dhabi, Dubai and Sharjah sit inside `U.A.E.`, individual member states sit inside `EU Countries` — and the list carries both `Bahrain` and an older misspelling `Behrain`, so summing the rows double-counts by a wide margin.
- Two published M2 figures agreeing exactly is a consistency check passing, not duplication: `Broad Money (M2) (A+B+C)` is the components decomposition (currency plus other deposits with SBP plus total bank deposits) and `Broad Money (M2) (A+B)` is the factors decomposition (net foreign assets plus net domestic assets). Both are the same stock viewed from opposite sides of the balance sheet.
- Ministry of Finance fiscal operations are reported **cumulatively from 1 July**, so each observation is a fiscal-year-to-date total and the series resets every July. Read as a quarterly flow the resulting sawtooth looks like revenue collapsing each summer; the dashboard states the convention on the page rather than silently differencing the series.
- PBS leaves multiple SDMX vintages online. For example, `CPI.xml` and [CPI-1.xml](https://www.pbs.gov.pk/wp-content/uploads/2020/07/CPI-1.xml) are distinct vintages; choose the later `prepared` attribute, not the prettier filename.

## Coverage gaps and what would close them

The remaining gaps are real source limitations, not missing dashboard buttons. FBR tax collection, PSDP releases, budget documents, and fiscal operations beyond the MoF SDMX feeds are PDF-only. A supervised PDF-table extraction programme—beginning with the official [FBR Revenue Collections](https://www.fbr.gov.pk/revenue-collections/142253/131355) listing and [MoF fiscal publication pages](https://www.finance.gov.pk/fiscal_main.html)—could close selected fiscal gaps, but needs reconciliation rules and human review of every new layout.

NEPRA generation/tariff material is PDF-first; the latest State of Industry research target is exceptionally large. OGRA is fully blocked to direct automated retrieval. Crop-level agricultural tonnage, a standalone poverty-headcount series, and monthly OCAC petroleum sales were not located in a machine-readable official form. For labour timeliness, PBS has a newer [Labour Force Survey 2024-25 annual report](https://www.pbs.gov.pk/wp-content/uploads/2020/07/LFS-2024-25-Annual-Report.pdf), but it is PDF rather than a refresh of the SDMX labour feed.

## Recommended next steps

1. **Operate Tier 1 regularly and preserve release evidence.** Run the end-to-end command on the weekly/monthly schedule, retain raw snapshots, and review the validation report before public briefing use.
2. **Add an opt-in EasyData adapter.** Store the API key only in deployment secrets, batch a small whitelist of approved series, expire/rotate it proactively at 90 days, and keep dashboard operation functional without it.
3. **Prioritise an inflation-contributions module.** The CPI SDMX data already include COICOP weights; develop a documented contribution-to-YoY method with base and timing tests rather than presenting an unverified decomposition.
4. **Build fiscal PDF extraction as a supervised Tier 2 workstream.** Start with FBR monthly revenue and MoF fiscal PDF tables, version every layout rule, and reconcile totals to publisher tables before promotion to Tier 1.
5. **Create a publication-lag register.** Surface each source’s last observation, last fetch, expected release cadence, and known publication lag. This prevents analysts from confusing a valid but lagged MoF figure with a current nowcast.
6. **Do not fill gaps with third-party estimates.** Continue the official-source-only rule. If a required official series remains PDF/manual/blocked, show the gap plainly and describe the acquisition method needed to close it.
